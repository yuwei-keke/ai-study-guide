# 让 AI Agent 遵守规范的技巧

## 一句话解释

AI Agent 不会自动遵守你的规矩——你需要在 CLAUDE.md 里明确写出规则，并且用具体的、可执行的语言描述。

## 小白类比

你请了一个新员工，你不能只说"好好干"，而要说"每天 9 点到岗、报告用这个模板、代码提交前要测试"。规则越具体，执行越到位。

## 通俗解释

**技巧 1：规则要具体**
- ❌ "代码要好看" → AI 不知道什么叫好看
- ✅ "每个函数不超过 50 行，命名用驼峰式" → 清晰可执行

**技巧 2：用"要"和"不要"**
- ✅ "要用 const 声明常量"
- ❌ "不要用 var"（不如正面表述）

**技巧 3：给示例**
- ✅ "注释格式参考：// 获取用户列表数据"

**技巧 4：分优先级**
- ✅ "必须遵守：不用 eval。建议遵守：函数不超过 50 行"

**技巧 5：及时更新**
- 项目变了，CLAUDE.md 也要跟着变
- 发现 AI 常犯的错，加一条规则

**技巧 6：用 .claude/ 目录**
- .claude/settings.json 可以配置更多选项
- 比如允许/禁止哪些工具

## 实际例子

一个有效的 CLAUDE.md 片段：

```markdown
## 代码规范
- 使用 ES6+ 语法（const/let，箭头函数）
- 每个函数写注释说明用途
- CSS 使用变量管理颜色
- 变量名用英文，注释用中文

## 禁止事项
- 不要用 document.write
- 不要用 eval
- 不要在 HTML 中写内联样式
- 不要把所有代码写在一个文件里

## Git 规范
- commit message 用中文
- 格式：[类型] 描述，如 [修复] 登录按钮无响应
```

## 适合做什么

- 写具体、可执行的规则
- 给 AI 正面的指令而非模糊的描述
- 定期更新 CLAUDE.md

## 不适合做什么

- 不要写太多规则（核心规则 10-20 条就够了）
- 不要写自相矛盾的规则
- 不要期望写一次就永远管用

## 关键概念

- **可执行的规则**：AI 能明确判断是否遵守的规则
- **正面表述**：告诉 AI "要做什么"比"不要做什么"更有效
- **迭代优化**：根据 AI 的表现不断调整规则
