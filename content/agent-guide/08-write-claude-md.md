# 如何写 CLAUDE.md

## 一句话解释

CLAUDE.md 是一个放在项目根目录的配置文件，用来告诉 Claude Code **"在这个项目里你应该遵守什么规则"**。

## 小白类比

想象你新雇了一个助手，你需要给他一份"工作手册"：

- 你希望他怎么做事情？
- 他不应该做什么？
- 项目有什么特殊要求？
- 工作流程是什么？

CLAUDE.md 就是这份"工作手册"。Claude Code 每次启动时都会读取它，然后按照你写的规则来工作。

## 通俗解释

当你用 Claude Code 做项目时，如果没有 CLAUDE.md，Claude Code 会按照自己的"默认习惯"来写代码。但每个项目都有自己的规范：

- 有的项目要求用中文注释
- 有的项目要求不用 TypeScript
- 有的项目要求修改前先说明计划
- 有的项目要求不删除某些文件

你可以在每次对话时重复说这些要求，但很麻烦。**CLAUDE.md 的作用就是把这些规则写一次，Claude Code 就会一直遵守。**

## CLAUDE.md 放在哪里

```
你的项目文件夹/
├── CLAUDE.md          ← 放在这里，项目根目录
├── index.html
├── style.css
├── ...
```

**注意**：文件名必须是 `CLAUDE.md`（全大写），放在项目最外层。

## CLAUDE.md 中应该写什么

### 1. 项目基本信息

```markdown
## 项目信息
这是一个 AI 学习知识库项目，用纯 HTML + CSS + JavaScript 实现。
目标用户是零基础学生，内容以中文为主。
```

### 2. 技术规范

```markdown
## 技术规范
- 使用纯 HTML + CSS + JavaScript
- 不使用任何框架（React、Vue等）
- 不使用 TypeScript
- CSS 使用变量管理主题色
- JavaScript 使用 ES6+ 语法
```

### 3. 工作流程

```markdown
## 工作流程
- 每次修改前先说明计划
- 每次修改后总结改了什么
- 不要删除已有文件，除非我明确要求
- 不要一次性大规模重构
```

### 4. 代码风格

```markdown
## 代码风格
- 代码中写中文注释
- 变量名用英文，注释用中文
- 每个函数不超过 50 行
- 文件名用小写加连字符（如 my-file.md）
```

### 5. 不要做什么

```markdown
## 禁止事项
- 不要引入 npm 依赖
- 不要创建 TypeScript 文件
- 不要修改 data/modules.json 的结构
- 不要删除 content/ 目录下的任何 .md 文件
```

## 完整示例：通用项目开发版

```markdown
# 项目规范

## 项目信息
[你的项目名称] — [一句话描述]

## 技术栈
- [列出使用的技术]
- [列出不使用的技术]

## 工作流程
1. 修改前先说明计划
2. 修改后总结变更
3. 不确定的地方先问我

## 代码规范
- 代码中写中文注释
- 变量名用英文
- 文件名用小写加连字符

## 禁止事项
- 不要删除已有文件
- 不要引入不必要的依赖
- 不要过度重构
```

## 完整示例：前端网页开发版

```markdown
# 前端项目规范

## 项目信息
这是一个纯前端网页项目，不需要后端。

## 技术栈
- HTML5 + CSS3 + JavaScript (ES6+)
- 不使用框架（React、Vue、Angular）
- 不使用 TypeScript
- 可以使用 CDN 引入第三方库

## CSS 规范
- 使用 CSS 变量管理颜色和尺寸
- 使用 Flexbox 或 Grid 布局
- 支持响应式设计（手机端）
- 支持暗色模式

## JavaScript 规范
- 使用现代 ES6+ 语法
- 异步操作用 async/await
- 错误处理用 try/catch
- 数据持久化用 localStorage

## 工作流程
1. 修改前先说：我打算修改 [文件名]，[修改内容]
2. 修改后说：已修改 [文件名]，[改了什么]
3. 如果不确定，先问我

## 禁止事项
- 不要使用 document.write
- 不要使用 eval
- 不要在 HTML 中写内联样式（除非必要）
- 不要删除已有的 CSS 变量
```

## 完整示例：零基础学生保护版

```markdown
# 零基础学生保护规范

## 重要说明
我是零基础学生，不是计算机专业。请严格遵守以下规则来保护我的项目安全。

## 安全规则
1. **绝对不要删除任何文件**，除非我明确说"请删除xxx"
2. **不要移动文件位置**，除非我明确同意
3. **不要修改已有文件的核心逻辑**，除非我明确要求
4. **每次只改一个文件**，改完确认没问题再改下一个
5. **修改前必须说明**：要改哪个文件、改什么内容、为什么改
6. **修改后必须总结**：改了什么、保留了什么、如何查看效果

## 代码保护
- 不要重写已经能正常工作的代码
- 不要"优化"我没要求优化的代码
- 不要引入我不了解的新技术
- 如果发现原有代码有问题，先告诉我，不要直接改

## 出错处理
- 如果不确定我的需求，先问我
- 如果修改可能导致问题，先告诉我风险
- 如果运行出错，告诉我应该看哪里（浏览器 F12 控制台）

## 解释要求
- 用通俗语言解释，不要堆砌术语
- 涉及新概念时，用类比帮我理解
- 每次修改后，告诉我如何运行查看效果
```

## 常见错误

- **写太多规则**：CLAUDE.md 不需要写成一本书，核心规则 10-20 条就够了
- **规则太模糊**：不要写"代码要好看"，要写"每个函数不超过 50 行"
- **不更新**：项目变了，CLAUDE.md 也要跟着更新
- **忘记放对位置**：必须在项目根目录，文件名必须是 `CLAUDE.md`
