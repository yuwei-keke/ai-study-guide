# 提示词模板大全

以下模板可以直接复制给 Claude Code / Codex 使用。每个模板都标注了适用场景和使用说明。

---

## 模板 1：让 Claude Code 做一个网页项目

### 适用场景
从零开始创建一个新的网页项目

### 提示词模板

```
【角色】你是一个前端开发专家，擅长用简洁的代码实现功能。

【项目背景】我想做一个 [项目名称]，目标用户是 [目标用户]。

【功能需求】
1. [功能1]
2. [功能2]
3. [功能3]

【页面要求】
- 首页：[首页要展示什么]
- [其他页面]

【技术要求】
- 使用 HTML + CSS + JavaScript
- 不需要后端
- 响应式设计，支持手机端
- 数据保存在浏览器本地存储中

【不要做什么】
- 不要用 React、Vue 等框架
- 不要用付费的第三方服务
- 不要添加不必要的复杂功能

【验收标准】
- 用浏览器直接打开 index.html 就能运行
- 手机端能正常显示和操作
- 所有功能都能正常使用
```

### 为什么这样写
- **角色设定**让 AI 知道以什么身份来工作
- **功能需求**明确列出，避免 AI 遗漏
- **不要做什么**防止 AI 过度设计
- **验收标准**让 AI 知道怎样算完成

## 模板 2：让 Claude Code 修改已有项目

### 适用场景
对已有的项目进行修改或添加功能

### 提示词模板

```
【任务】请修改我现有的项目，添加 [功能名称] 功能。

【当前项目情况】
- 项目是一个 [项目类型]
- 主要文件有：[列出主要文件]
- 目前已经有的功能：[列出功能]

【修改需求】
1. [具体修改内容1]
2. [具体修改内容2]

【修改要求】
- 只修改需要改的文件，不要动其他文件
- 修改前先说明你打算改哪些文件
- 修改后检查是否有错误
- 保持现有功能正常运行

【不要做什么】
- 不要重构整个项目
- 不要改变现有的代码风格
- 不要删除现有的功能
```

### 为什么这样写
- **当前项目情况**让 AI 了解现状
- **只修改需要改的文件**防止 AI 乱改
- **修改前先说明**让你能确认计划

## 模板 3：让 Claude Code 修复 Bug

### 适用场景
项目有错误，需要修复

### 提示词模板

```
【问题描述】我的项目有一个 bug：[描述问题现象]

【复现步骤】
1. [步骤1]
2. [步骤2]
3. 出现了 [错误现象]

【期望行为】正确的行为应该是 [期望行为]

【实际行为】实际发生的是 [实际行为]

【错误信息】
如果有报错信息，请粘贴在这里：
[粘贴错误信息]

【要求】
- 先分析可能的原因
- 给出修复方案
- 修复后验证问题是否解决
- 不要修改无关的代码
```

### 为什么这样写
- **复现步骤**帮助 AI 理解问题
- **期望 vs 实际**让 AI 明确目标
- **错误信息**是定位问题的关键线索

## 模板 7：让 Claude Code 检查安全风险

### 适用场景
项目准备上线，需要检查安全性

### 提示词模板

```
【任务】请检查我的项目是否有安全风险。

【检查范围】
- 所有代码文件
- 配置文件
- 依赖项

【重点检查】
1. API Key 是否暴露在代码中
2. 是否有 XSS 漏洞
3. 是否有敏感信息泄露
4. 依赖项是否有已知漏洞

【要求】
- 列出所有发现的风险
- 按严重程度排序（高/中/低）
- 给出修复建议
- 如果能自动修复，直接修复
```

## 模板 9：让 Claude Code 做小红书内容生成工具

### 适用场景
做一个能批量生成小红书风格内容的工具

### 提示词模板

```
【角色】你是一个全栈开发专家，擅长做内容创作工具。
```

## 使用这些模板的注意事项

1. **方括号 `[ ]` 中的内容需要你替换成实际内容**
2. **模板是起点，不是终点**——根据实际情况调整
3. **复杂任务要分步骤**——不要一次给太多需求
4. **AI 的输出需要你检查**——不要盲目信任
