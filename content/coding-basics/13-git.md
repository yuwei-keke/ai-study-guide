# Git 是什么

## 一句话解释

Git 是代码的"时光机"——它能记录你每一次修改，让你随时回到之前的任何一个版本。

## 小白类比

你写论文时，是不是会保存多个版本："论文v1.doc"、"论文v2.doc"、"论文最终版.doc"、"论文最终版改.doc"？Git 就是自动帮你做这件事的工具，而且更强大、更智能。

## 通俗解释

Git 是目前世界上最流行的版本控制系统，几乎所有的软件项目都在用它。

**Git 能帮你做什么：**
1. **记录历史**：每次修改都有记录，谁改的、改了什么、什么时候改的
2. **随时回退**：改坏了？一键回到上一个好版本
3. **多人协作**：多个人同时改同一个项目，Git 自动合并
4. **分支管理**：可以创建"平行宇宙"，在不同分支上做不同功能

**Git 的基本工作流程：**
1. 修改文件（编辑代码）
2. 暂存修改（git add）
3. 提交修改（git commit，保存一个快照）
4. 推送到远程（git push，上传到 GitHub）

## 实际例子

```bash
# 初始化一个 Git 仓库
git init

# 查看当前状态
git status

# 暂存所有修改
git add .

# 提交修改，附带说明
git commit -m "添加了登录功能"

# 查看历史记录
git log

# 回退到上一个版本
git reset --hard HEAD~1
```

## 适合做什么

- 管理代码版本，记录每次修改
- 多人协作开发同一个项目
- 用分支做功能开发和 bug 修复
- 配合 GitHub 做代码托管

## 不适合做什么

- 不适合管理大型二进制文件（如视频、图片）
- 不要忘记写 commit 说明（否则以后看不懂改了什么）
- 不要在 main 分支上直接改代码（应该建新分支）

## 关键概念

- **仓库（Repository）**：Git 管理的项目文件夹
- **提交（Commit）**：保存一个版本的快照
- **分支（Branch）**：代码的平行宇宙，互不干扰
- **合并（Merge）**：把分支的修改合并回主分支
