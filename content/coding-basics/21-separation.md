# 前后端分离是什么

## 一句话解释

前后端分离就是"前端管展示，后端管数据"——两者通过 API 通信，各干各的，互不影响。

## 小白类比

餐厅有两种运营模式：

**不分离**：厨师做好菜自己端出去给顾客（前端后端混在一起）

**分离**：厨师在厨房做菜，服务员负责端菜和接待顾客（前后端各司其职）

## 通俗解释

**传统模式（不分离）：**
- 后端直接生成 HTML 页面返回给浏览器
- 前后端代码混在一起
- 改个页面样式可能要重启后端

**前后端分离：**
- 前端：独立的 HTML/CSS/JS 项目，负责页面展示
- 后端：只提供 API 接口，返回 JSON 数据
- 两者通过 HTTP 请求通信

**好处：**
1. 前后端可以并行开发，互不等待
2. 同一个后端可以服务网页、手机 App、小程序
3. 前端可以独立部署和更新
4. 团队分工更清晰

## 实际例子

用户打开一个商品页面：

**前后端分离的做法：**
1. 前端加载 HTML/CSS/JS
2. 前端通过 API 请求商品数据：`GET /api/products/123`
3. 后端查询数据库，返回 JSON：`{"name": "T恤", "price": 99}`
4. 前端拿到数据，渲染到页面上

```javascript
// 前端代码
const res = await fetch('/api/products/123');
const product = await res.json();
document.getElementById('name').textContent = product.name;
```

## 适合做什么

- 中大型 Web 项目
- 需要同时支持网页和 App 的项目
- 多人团队协作开发

## 不适合做什么

- 简单的静态页面不需要分离
- 个人小项目可能过度设计

## 关键概念

- **RESTful API**：一种 API 设计规范
- **JSON**：前后端传输数据的格式
- **CORS**：跨域请求问题，前后端分离时经常遇到
